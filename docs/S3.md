# S3-Compatible Storage

Generic S3-compatible configuration, with presets/documentation for:

- **Backblaze B2** (via its S3-compatible API endpoint)
- **Wasabi**
- **Amazon S3**
- Any other S3-compatible provider (MinIO, etc.)

Prices are intentionally not documented here — check the provider directly.

## What you need

- An endpoint URL (e.g. `s3.us-west-002.backblazeb2.com` for Backblaze B2,
  `s3.wasabisys.com` for Wasabi, or your region's AWS endpoint)
- A region (some providers ignore this; set it anyway if given one)
- A bucket name
- An access key ID and secret access key, scoped to that bucket only if
  your provider supports scoped keys (recommended: least privilege)

## Setting it up

```bash
abm storage add --type s3 --name backblaze \
    --endpoint s3.us-west-002.backblazeb2.com \
    --region us-west-002 \
    --access-key <your-access-key-id> \
    --secret-key <your-secret-access-key>
```

This creates the rclone remote non-interactively
(`internal/rclone.CreateS3Remote`) and registers it in `config.yaml` (the
access/secret key live only in `rclone.conf`, never in `config.yaml`).

> Passing `--secret-key` on the command line puts it in shell history for
> the duration of your terminal session; prefer running this command from a
> script that reads the key from a file or secret manager rather than typing
> it interactively, where practical.

## Testing

```bash
abm storage test backblaze
```

## Object Lock / immutability

**For ransomware/stolen-credential resilience, use a destination with
Object Lock / WORM (Write Once, Read Many) support.** Backblaze B2 and AWS
S3 both support Object Lock in compliance or governance mode: once set, even
someone holding valid write credentials cannot delete or overwrite a locked
object until its retention period expires. This is the strongest
destination type in this project's threat model — see
[THREAT-MODEL.md](THREAT-MODEL.md).

Enabling Object Lock is done on the bucket itself (via your provider's
console/API) before Auto-Backup-Manager writes to it; this project does not
configure Object Lock for you. Mark the destination accordingly so it's
clear in `config.yaml` and `abm storage list`:

```bash
abm storage add --type s3 --name backblaze-locked --immutable \
    --endpoint ... --access-key ... --secret-key ...
```

(`--immutable` is advisory/documentation metadata; it does not itself
enable Object Lock on the bucket.)
